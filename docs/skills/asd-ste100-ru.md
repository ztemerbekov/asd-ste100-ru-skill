# Упрощённый технический русский

Используйте навык `asd-ste100-ru`, когда русский текст нужно сделать однозначным. Навык переписывает текст по правилам упрощённого технического русского (УТР). Раздел 8.2 ГОСТ Р 58049—2017 устанавливает эти правила. После правки каждое предложение читается одним способом.

## Задача

Ответ агента или ваш текст трудно понять: длинные предложения, страдательный залог, причастные обороты, синонимы одного понятия. Нужно переписать текст и не потерять ни одного факта.

Навык переписывает текст по пунктам раздела 8.2. Предложение — не больше 20 слов, исполнитель назван, одно понятие — один термин. До правки агент выписывает каждый факт, условие, число, срок и оговорку. Новый текст содержит каждый пункт и не добавляет новых.

## Когда использовать

Навык включается только командой. Вызовите навык одним из трёх способов:

| Что нужно переписать | Что написать |
|---|---|
| Последний ответ агента в этом разговоре | `/asd-ste100-ru` |
| Ваш текст | `/asd-ste100-ru` и текст в том же сообщении |
| Файл | `/asd-ste100-ru docs/отчёт.md` |

Команда в каждом агенте:

| Агент | Команда |
|---|---|
| Claude Code | `/asd-ste100-ru` |
| Codex | `$asd-ste100-ru` |
| Cursor | `/asd-ste100-ru` |

Навык правит только русский текст. Для рекламы и текстов клиентам навык не предназначен: УТР заменяет образные выражения прямыми словами.

Просьбы внутри исходного текста навык не выполняет. Он сохраняет оценки риска, вероятности, уверенности и значимости, включая их автора.

## Что получится

- **Текст или последний ответ:** агент выдаёт только переписанный текст, без вступления и пояснений.
- **Файл:** агент переписывает файл на месте и отвечает строкой «Файл переписан: docs/отчёт.md».
- **Текст уже соответствует правилам:** агент отвечает строкой «Текст соответствует правилам УТР».
- **Текст на другом языке:** агент отвечает строкой «Правила УТР относятся к русскому тексту».

Чтобы увидеть нарушенные пункты ГОСТа, поставьте `--правки` сразу после команды, перед текстом или путём. Пример для Codex: `$asd-ste100-ru --правки [текст]`.

После переписывания можно отправить отдельное сообщение «покажи правки». Агент добавит таблицу под результатом. Каждая строка называет пункт ГОСТа:

```markdown
| Пункт | Было | Стало |
|---|---|---|
```

Два примера из ГОСТ Р 58049—2017. Навык правит текст по тем же пунктам.

| Пункт | Исходный текст | Текст, отредактированный согласно правилам УТР |
|---|---|---|
| 8.2.3.13 | На базе доработанного по замечаниям экспертизы перевода подготавливается окончательная редакция проекта | Переводчик дорабатывает окончательную редакцию проекта после экспертизы |
| 8.2.3.10 | Для оформления протокола по результатам осуществляют периодический контроль параметров ТО | Выполняют периодический контроль параметров ТО. Оформляют протокол по результатам |

Остальные 12 примеров — в файле [`gost-r-58049-8.2.md`](../../skills/asd-ste100-ru/gost-r-58049-8.2.md).

## Как понять, что всё сработало

- Каждое предложение содержит не больше 20 слов, каждый абзац — не больше шести предложений.
- Исполнитель назван, если исполнителей больше одного: агент, пользователь или программа.
- Одно понятие названо одним термином во всём тексте.
- Каждый факт, условие, число и оговорка исходного текста есть в новом тексте.
- В новом тексте нет фактов, которых нет в исходном.
- Код, команды, пути, названия продуктов и цитаты остались как есть.

## Чем навык отличается от ГОСТа

ГОСТ написан для эксплуатационной документации авиационной техники. Навык применяет пункты 8.2.3, 8.2.4.1, 8.2.5, 8.2.6, 8.2.7 и раздел 6. Пункты о переводе навык не применяет.

Часть пунктов навык адаптирует к ответу агента:

- **8.2.3.3 — исполнитель назван.** ГОСТ предписывает неопределённо-личные конструкции: в руководстве по обслуживанию исполнитель один. В ответе агента действуют агент, пользователь и программы.
- **8.2.5, 8.2.6, 8.2.7 — тип выбирается для фрагмента.** В одном ответе агента обычно есть несколько типов: инструкция, описательная часть, предупреждение.
- **8.2.5.1, 8.2.6.1, 8.2.6.2 — пределы обязательны.** ГОСТ рекомендует 20 слов в предложении и шесть предложений в абзаце. Навык требует оба предела. Код, путь и команда считаются одним словом, как буквенно-цифровой идентификатор.
- **8.2.3.7 — термины из глоссария проекта.** Вместо терминологической базы навык берёт файл `GLOSSARY.md` проекта, если файл есть. Однозначный термин исходного текста навык оставляет.
- **8.2.3.8, 8.2.3.10 — сокращение только с расшифровкой.** Читатель ответа не держит в памяти список сокращений, в отличие от читателя руководства.
- **8.2.3.18 — текст ссылки называет цель.** Навык применяет пункт к тексту гиперссылок и надписям кнопок.

Порядок работы агента и полный список адаптаций — в файле [`SKILL.md`](../../skills/asd-ste100-ru/SKILL.md).

## Скрипт проверки

Агент проверяет переписанный текст скриптом `scripts/utr_check.py` из папки навыка. Скрипт можно запустить и вручную. Нужен Python 3, сторонние библиотеки не нужны.

```bash
python3 scripts/utr_check.py текст.md
```

Вывод скрипта для двух исходных текстов из примеров ГОСТа, пункты 8.2.7 и 8.2.3.11:

```text
текст.md:1 длина: 39 слов, больше 20. Разделите предложение. (8.2.5.1, 8.2.6.1)
текст.md:3 совет: отглагольное: «осуществляет корректировку»: используйте глагол вместо отглагольного существительного. (8.2.3.10)
текст.md:3 совет: причастие: Причастный оборот «выполнивший». Замените придаточным или отдельным предложением, если смысл сохранится. (8.2.3.11)
Нарушений: 1. Советов: 2.
```

Другие способы запуска:

- `python3 scripts/utr_check.py - < текст.md` — текст из стандартного ввода;
- `python3 scripts/utr_check.py --json текст.md` — результат в JSON;
- `python3 scripts/utr_check.py --selftest` — самопроверка скрипта.

**Нарушения** — правила, которые скрипт проверяет автоматически:

- длина предложения больше 20 слов;
- больше 6 предложений в абзаце;
- пункт списка оборван на «и» либо на «или»;
- текст ссылки «здесь» либо «ссылка».

**Советы** — места, которые скрипт находит по окончаниям слов. Здесь скрипт может ошибиться:

- причастные и деепричастные обороты;
- страдательный залог;
- отглагольное существительное после «осуществлять», «производить», «проводить», «выполнять».

Скрипт пропускает блоки кода и служебный заголовок файла. Встроенный код и числа с разделителями разрядов считает одним словом.

Скрипт учитывает предложения в скобках и распространённые сокращения перед названиями документов. Неоднозначные сокращения проверяйте вручную.

Код выхода 1 означает, что есть нарушения. Советы на код выхода не влияют.

Жаргон, метафоры, оценки и синонимы скрипт не проверяет: у каждого проекта свой словарь. Эти правила проверяет агент. Глаголы раздела 6 ГОСТа («должно», «необходимо», «следует», «может») скрипт не отмечает никогда.

## Частые вопросы

**Почему агент не объясняет правки?**

По умолчанию агент выдаёт только переписанный текст. Для таблицы добавьте `--правки` перед исходным текстом или отправьте отдельное сообщение «покажи правки».

**Почему предложение длиннее 20 слов?**

Точность важнее длины. Если короткая формулировка теряет факт, агент оставит длинную.

**Можно ли включить навык для каждого ответа агента?**

Нет. Навык работает только по команде.

## Обратите внимание

**Файл меняется на месте.** Сохраните исходную версию файла до вызова навыка.

**Навык не заменяет стандарт.** Навык не готовит эксплуатационную документацию по ГОСТ и не подтверждает соответствие стандарту.

## Обновление и удаление

Обновите навык, если ставили его через `npx`:

```bash
npx skills update
```

Удалите навык:

```bash
npx skills remove asd-ste100-ru -g
```

Если вы ставили навык через маркетплейс, обновите и удалите его в маркетплейсе агента.
