# AGENTS.md

Правила для агентов, которые работают в этом репозитории.

## Назначение репозитория

Репозиторий публикует один навык `asd-ste100-ru`. Навык переписывает русский текст по разделу 8.2 ГОСТ Р 58049—2017 — на упрощённый технический русский (УТР).

## Agent skills

### Issue tracker

Issues live in GitHub Issues of ztemerbekov/asd-ste100-ru-skill (gh CLI). See `docs/agents/issue-tracker.md`.

### Triage labels

Default vocabulary: needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Режимы работы

Выберите режим до первой записи в GitHub.

- **Локальная правка.** Пользователь просит изменить файлы и не просит коммит, push, пул-реквест или слияние. Измените файлы, сохраните чужие изменения в рабочей копии, запустите проверку.
- **Публикация.** Пользователь просит коммит, push, пул-реквест или слияние. Выполните шаги ниже.

1. Проверьте рабочую копию. Чужие незакоммиченные изменения оставьте вне коммита.
2. Создайте ветку от свежего `main`.
3. После последней правки запустите полную проверку из раздела «Проверка».
4. Откройте пул-реквест в `main`. В описании укажите, что изменилось, и результат проверки.
5. Когда все проверки CI зелёные, слейте пул-реквест сами. Команда владельца не нужна. Способ слияния — squash.
6. После слияния обновите `main` в рабочей копии и запустите полную проверку.

## Структура навыка

Навык лежит в папке `skills/asd-ste100-ru/`. Папка самодостаточна: агент ставит навык из GitHub без сборки. Ссылки внутри навыка ведут только на файлы этой папки.

`SKILL.md` содержит в frontmatter поля `name`, `description`, `disable-model-invocation` и `metadata.author`. Версия навыка — в манифестах и тегах Git, а не в frontmatter.

Кейсы в `evals/` — материал для сопровождающего. Навык не читает их во время работы.

## Текст ГОСТа

Правила и примеры ГОСТа переносите дословно, с номерами пунктов. Сверяйте текст со сканом стандарта.

Своё в навыке — только слой применения: какие пункты навык берёт и как адаптирует. Каждое отступление от ГОСТа помечайте как адаптацию или толкование в разделе «Применение к ответу агента» файла `SKILL.md`.

Входные тексты в `evals/cases/` — только примеры ГОСТа. В `evals/agent-cases/` проверяйте ответы агента и применение навыка. Указывайте источник текста: реальный ответ или составленный пример.

## Публичная витрина

Изменение имени, описания или поведения навыка проверяйте сразу во всех местах:

- `README.md` и `docs/skills/asd-ste100-ru.md`;
- `skills/asd-ste100-ru/agents/openai.yaml`;
- `plugin.json`, `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`, `.codex-plugin/plugin.json`, `.cursor-plugin/plugin.json`, `.cursor-plugin/marketplace.json`;
- `CHANGELOG.md`.

README, страница навыка и описания в манифестах — только на русском. README — витрина навыка. Таблицы навыков в README нет: навык в репозитории один. Подробности — на странице навыка.

Навык вызывается только командой. Поле `disable-model-invocation: true` в `SKILL.md` и поле `allow_implicit_invocation: false` в `agents/openai.yaml` меняйте вместе.

Пишите README, страницу навыка и CHANGELOG по правилам УТР. Проверьте текст скриптом навыка:

```bash
python3 skills/asd-ste100-ru/scripts/utr_check.py README.md
```

В описании пул-реквеста покажите итоговые значения манифестов: имя, отображаемое имя, описание и ключевые слова.

## Проверка

Во время работы запускайте самую узкую проверку:

- README и `docs/` — `git diff --check` и `python3 scripts/validate-links.py`;
- манифесты и `assets/` — `python3 scripts/validate-marketplaces.py` и `git diff --check`;
- навык, скрипты и кейсы — полный набор ниже.

Перед пул-реквестом запустите полный набор один раз:

```bash
bash -n scripts/validate-skills.sh
./scripts/validate-skills.sh
git diff --check
```

Проверки подтверждают структуру, а не смысл. Ручную проверку по кейсам `skills/asd-ste100-ru/evals/` запускайте только по просьбе владельца. Результат записывайте в пул-реквест или выпуск, а не в репозиторий.

## Авторизация в GitHub

Используйте глобальную авторизацию `gh`. Токены GitHub не читайте, не выводите и не сохраняйте в файлы.

## Простота

- Новый генератор, зависимость, манифест или обязательную проверку обсудите с владельцем до добавления.
